# MOSI V9.4: Cross-fitted calibration + staged positive residual

## Purpose

V9.1 showed that a learned expert can improve ordinary-positive Validation MAE, but
hurt other sentiment regions. V9.2 then collapsed its gate to almost always off.
V9.3 removed the gate and learned non-zero magnitudes, but could not identify which
samples should receive them.

V9.4 separates three questions:

1. Can a reference correction be estimated without using each Train sample's own
   label in that calibration fit?
2. Can the positive residual magnitude be learned?
3. Can an active/inactive classifier identify where that magnitude should be used?

## Important OOF scope

The grouped folds are out-of-fold **at the calibration layer**. Every Train
calibrated reference is generated by a ridge-Huber calibrator whose fit excludes
that sample's group.

The historical V7.1 DLF and Teacher checkpoints were trained on the full Train
split. Their frozen predictions are therefore not strict end-to-end OOF
predictions. V9.4 records this limitation in the summary and must not be described
as a fully retrained OOF DLF system.

A future strict experiment would need five independently trained V7.1 pipelines,
one per held-out Train fold.

## Cross-fitted reference

The calibration design includes:

- original V7.1 Hybrid;
- V7.1 Student and base anchor;
- global and region simplex committees;
- each frozen Teacher prediction;
- Teacher mean, median, standard deviation and range.

Groups are formed from the sample ID prefix before `$_$` when available, keeping
segments from the same source video in one fold. Five sentiment regions are used
for approximate group stratification.

For each ridge value and calibration blend:

1. fit robust Huber ridge on four folds;
2. predict the held-out fold;
3. repeat until every Train sample has one cross-fitted prediction;
4. select ridge/blend by Train-OOF MAE with small worst-region and fold-stability
   penalties;
5. fit the selected calibrator on all Train for Valid/Test deployment.

`blend=0` is always legal.

## Stage A: residual magnitude

The target is

```text
target = clip(label - OOF_calibrated_reference, 0, max_correction)
target = 0 for label <= 0
```

The gate is frozen. Only the specialist adapter and magnitude head are trained.

Validation checkpoint selection uses:

- active-target Huber as the primary term;
- overall residual Huber;
- false magnitude on zero-target samples.

## Stage B: activation classifier

The magnitude representation is frozen. Only the gate head is trained.

The active target is:

```text
positive_residual_target > residual_margin
```

Training uses positive-class weighted focal BCE. This directly addresses the
V9.2 all-off solution. Validation reports average precision, recall, specificity,
balanced accuracy and predicted active rate.

## Final Validation-only policy families

- `legacy_reference`
- `legacy_beta_search`
- `zero_shrinkage`
- `oof_calibrated_reference`
- `oof_magnitude_only`
- `oof_gated_residual` with soft or thresholded gate

The residual families are added only to the matching calibrated reference. They
are not attached to unrelated beta/shrinkage bases.

Test is collected only after the calibrator, magnitude checkpoint, gate checkpoint
and final policy have all been frozen.

## Audit

```bash
python3 scripts/audit_oof_positive_residual_v94.py \
  --run-dir result/oof_positive_residual_v94/mosi/seed_1111 \
  --expected-reference-mae 0.6994764 \
  --reference-tolerance 0.0002
```

The audit checks:

- V7.1 reference reproduction;
- unique Train/Test sample IDs;
- no source group crossing calibration folds;
- complete fold coverage;
- bounded residual targets and outputs;
- zero-blend fallback;
- serialized calibrator matching the search table;
- contribution flags matching the selected policy;
- exact attribution for legacy/beta/zero-shrinkage selections.

## Interpretation

The strongest evidence for a successful residual route is:

```text
source=oof_gated_residual
gamma>0
residual_training_contributed=True
```

`oof_magnitude_only` with positive gamma means the magnitude is useful but the
gate is not. `oof_calibrated_reference` means the cross-fitted calibration helped
without the residual heads. Any legacy or zero-shrinkage selection means V9.4 did
not obtain enough Validation support to deploy the new learned path.
